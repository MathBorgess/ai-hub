### N1 — P2: an accepted but silent sidecar connection blocks every session and shutdown

- **Location:** `aihub-memory/src/ai_memory.rs:309`, `:333`; awaited from `aihubd/src/lib.rs:1163` while `handle` holds state from `:781`; shutdown waits for that same lock at `:651`.
- **Scenario:** ai-memory accepts the request but hangs or keeps its response stream open. Unbounded connect/write/read-to-EOF has no deadline. A switch has already launched its incoming harness, but recording never returns; every client list/input/merge, output-state update and graceful shutdown waits for the registry. Offline fallback is reached only on an error, not a stalled connection.
- **Fix:** give the full delivery a deadline and response-size limit, spool on expiry, and perform delivery/draining outside the registry critical section.
- **Coverage gap:** fake servers either respond and close or use refused connections; none accepts and never finishes.

### N2 — P2: false MCP success removes undelivered records

- **Location:** `aihub-memory/src/ai_memory.rs:153`, `:195`, `:203`; HTTP body parsing `:350`.
- **Scenario:** server returns HTTP 200 with `{"jsonrpc":"2.0","id":1,"result":{"isError":true,"content":[]}}`. The adapter checks only top-level `error`, calls this Delivered and deletes the spool entry. A 200 empty/malformed body also succeeds. An SSE/chunked response containing an RPC error fails raw JSON parsing and is likewise treated as success.
- **Fix:** decode the actual HTTP/MCP framing and require a valid matching successful tool result (including `isError != true`) before acknowledging/removing a record.
- **Coverage gap:** tests exercise a simplified success body, 401 and refused port, not tool-level errors, malformed success or advertised SSE transport.

### N3 — P2: draining truncates the only copy of still-undelivered records

- **Location:** `aihub-memory/src/ai_memory.rs:203`, especially `:211`.
- **Scenario:** spool holds 25 records; one live call drains 20, then opens the spool with truncate before writing the remaining five. A process kill or disk-full error during rewrite destroys pending records that were never delivered. The caller ignores the drain error (`:104`).
- **Fix:** write and sync the remainder to a private temporary file, atomically replace the spool, and serialize append/drain access; surface retention failures.
- **Coverage gap:** normal drain test only proves a successful small-spool removal; no interrupted rewrite or append/drain concurrency test exists.

### N4 — P2: offline spool cannot preserve the handoff when its temporary checkout goes away

- **Location:** `aihub-memory/src/ai_memory.rs:33`, `:89`, `:122`, `:129`, `:261`.
- **Scenario:** switch while backend is offline, then confirm Discard or later remove the kept temporary checkout. The spool contains only IDs, labels and file paths, not the sanitized brief. On later drain the brief is missing, so delivery substitutes a generic from/to sentence and deletes the pending record. Original goal/decisions/output are unrecoverable from the spool. Even online, the payload copies only Goal and empty context arrays, omitting the brief's decisions and normal-case session/from/to identity.
- **Fix:** spool an immutable sanitized handoff payload with stable identity and required context at creation, and deliver that payload instead of rereading mutable temporary files.
- **Coverage gap:** drain fixtures retain every original brief until delivery; the live test checks a project heading, not round-tripped context.

### N5 — P2: spool storage has no bound or independent recovery

- **Location:** `aihub-memory/src/ai_memory.rs:29`, `:104`, `:175`, `:223`.
- **Scenario:** prolonged backend outage or persistent 401 plus repeated switches appends indefinitely. `MAX_DRAIN_PER_CALL` caps only deliveries, not stored rows/bytes; recovery loads the entire file. With no later successful handoff, a recovered backend never drains at all. On a constrained disk the accumulated spool eventually causes append/other application writes to fail.
- **Fix:** enforce explicit byte/record limits with visible overflow handling and retry pending delivery independently of new handoffs; stream bounded batches.
- **Coverage gap:** no size-bound, over-limit, restart-retry or recovery-without-new-handoff test.

### N6 — P2: lane discovery introduces an unbounded blocking CLI call under the registry lock

- **Location:** `aihub-router/src/lib.rs:221`, `:313`, `:334`; daemon route calls `aihubd/src/lib.rs:1012`, `:1048`.
- **Scenario:** first route choosing Cursor/Antigravity calls `cursor-agent --list-models` or `agy models`; CLI waits for authentication, network or input indefinitely. Synchronous `Command::output()` blocks its executor thread while the daemon owns the global state mutex. Other sessions and shutdown stop progressing. The classifier's ten-second timeout does not cover this separate model-list call.
- **Fix:** fetch/cache model metadata asynchronously outside the registry lock with a deadline, bounded output and child cleanup; routing must consume an already available snapshot.
- **Coverage gap:** `aihub-router/tests/model_lane.rs` supplies list fixtures and does not exercise a hanging executable.

### N7 — P2: launchd setup cannot find harness binaries installed only in the user's shell PATH

- **Location:** `packaging/launchd/io.mathborgess.aihubd.plist:14`; bare executable recipes `aihub-pty/src/harness.rs:25`, `:37`, `:48`, `:59`; installer `scripts/install.sh:299`.

The LaunchAgent provides no PATH or resolved harness paths, so a launchd environment lacking those directories cannot spawn the harness. Both installer checks can still pass because they verify only the sidecar and socket, not a harness launch. The shell export does not configure the agent's environment.

- **Coverage gap:** fake `/bin/sh` headless tests and plist templates do not exercise installed launchd harness discovery.

### N8 — P2: valid home paths break plist rendering

- **Location:** `scripts/install.sh:250`, `:255`.
- **Scenario:** home path `/Volumes/Work & Data/user` is inserted unescaped into a sed replacement; `&` expands to the matched placeholder. Even if sed escaping is fixed alone, raw `&` or `<` in the resulting XML makes the plist invalid. Bootstrap therefore fails for otherwise valid paths. Spaces alone are correctly shell-quoted.
- **Fix:** render plist string values with a plist/XML serializer, validate the finished file and install atomically.
- **Coverage gap:** no executable installer tests are present; shellcheck cannot prove value escaping.

### N9 — P2: installation reports failure before freshly bootstrapped services are ready

- **Location:** `scripts/install.sh:299`, `:311`, `:318`.
- **Scenario:** bootstrap succeeds but sidecar initialization or daemon socket creation takes longer than the single immediate check. Curl gets refused/socket is absent, so install exits nonzero even though services become healthy moments later; optional hooks are skipped. A service accepting but never responding also hangs the unbounded curl.
- **Fix:** bounded readiness polling for both services, with per-request timeout and a clear final failure after the deadline.
- **Coverage gap:** sidecar loop script's temporary startup is not execution of this installer health path.

### N10 — P2: handoffs are recorded under ephemeral session directories instead of repository identity

- **Location:** `aihub-memory/src/ai_memory.rs:236`, `:252`; daemon brief location `aihubd/src/lib.rs:1110`; worktree creation `aihub-git/src/lib.rs:147`.
