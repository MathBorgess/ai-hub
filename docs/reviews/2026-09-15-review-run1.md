## Findings

Severity: P1 = high impact; P2 = medium. Ordered by severity, then the brief's focus order.

### F1 — P1: Opaque OAuth/CSRF values survive handoff redaction and reach disk

- **Location:** `aihub-memory/src/redact.rs:16`; sink `aihub-memory/src/brief.rs:75`; extraction `aihub-memory/src/transcript/claude.rs:86`.
- **Failure scenario:** A matching outgoing transcript contains an assistant excerpt or last user message such as `{"refresh_token":"fabricated-refresh-value","csrfToken":"fabricated-csrf-value"}`. Neither value has a supported Bearer/JWT/sk-/GitHub prefix, so extraction and brief writing preserve both verbatim in `.aihub/handoffs/NN.md`. The same happens to opaque OAuth access tokens. A later `git add -A` can also commit this generated brief. This is a concrete Secrets-rule violation; the examples are fabricated.
- **Fix:** Redact credential-bearing fields and assignments before extracting/persisting text, with fabricated opaque OAuth/CSRF regression cases and an explicit secret-safe handoff boundary.

### F2 — P1: Keep and successful merges silently delete ignored, uncommitted files

- **Location:** `aihub-git/src/lib.rs:311` and `:317`; equivalent forced removals at `:383` and `:431`.
- **Failure scenario:** A user creates a valuable ignored file in the session worktree (for example `notes.local` matched by `.gitignore`) and selects Keep Branch or Squash. `status --porcelain`, `add -A` and the preview omit it. `worktree remove --force` deletes it anyway. The preserved branch/merge cannot recover its contents, and the preview did not disclose the deletion.
- **Fix:** Retain the worktree or explicitly inventory and preserve ignored/uncommitted content before any non-Discard removal; avoid force-removal as the default success cleanup.

### F3 — P1: Discard deletes whichever branch is currently checked out, without validating session ownership

- **Location:** `aihub-git/src/lib.rs:305` and `:340`.
- **Failure scenario:** During a session, the user/harness switches the shadow worktree to an existing unmerged `feature/user-work` branch not checked out elsewhere. Confirming Discard removes that worktree and runs `branch -D feature/user-work`, even though the user intended to discard the ephemeral `session/<id>` branch. Changes to branch identity are not represented in the daemon's diff-only confirmation.
- **Fix:** Validate canonical worktree registration and its expected session branch before finishing; refuse a changed branch instead of deleting the current branch by discovery.

### F4 — P1: A kill request is treated as a completed stop before destructive finalization

- **Location:** `aihubd/src/lib.rs:585`; implementation `aihub-pty/src/spawn.rs:204`.
- **Failure scenario:** Confirmation calls `PtyHandle::kill`, which only invokes the child killer and returns without waiting for exit. The daemon immediately marks the session inactive, takes a supposedly stopped diff and commits/removes the worktree. A child still completing termination, or a surviving descendant, can write after that diff or after the snapshot commit and lose the write during forced removal. Shutdown similarly reports inactive without reaping the stopped child (`aihubd/src/lib.rs:354`).
- **Fix:** Make stop a bounded terminate/wait/escalate/reap barrier for the owned process group, then compute the final preview and perform git finalization.

### F5 — P1: Switching launches two writable harnesses in the same worktree

- **Location:** `aihubd/src/lib.rs:653` and `:667`.
- **Failure scenario:** `/switch` extracts context while the outgoing harness is still working, starts the incoming harness with an actionable prompt in the same directory, and only then requests termination of the old one. Both can modify the same file; the incoming harness may overwrite an outgoing write based on an already stale brief. The existing test intentionally requires this overlap (`aihubd/src/lib.rs:824`).
- **Fix:** Quiesce and reap the outgoing harness, extract its final context, and only then launch the incoming harness; preserve a recoverable stopped state on spawn failure.

### F6 — P2: Dropping a PTY handle does not trigger its intended child cleanup

- **Location:** `aihub-pty/src/spawn.rs:118`; cleanup `:38`.
- **Failure scenario:** Spawn a long-running child and drop its only public handle without explicitly killing it. The reader thread owns an `Arc<PtyInner>` while blocking on PTY output, so `PtyInner::drop` cannot run to kill the child. Once that thread eventually releases the final Arc, Drop can attempt to join the very same reader thread. Cleanup is attached to the wrong lifetime.
- **Fix:** Give the public handle explicit independent shutdown ownership; let the reader hold only the state it needs and never join its own thread from Drop.

### F7 — P2: One blocked PTY input request freezes all sessions and graceful shutdown

- **Location:** `aihubd/src/lib.rs:460` and `:515`; blocking write `aihub-pty/src/spawn.rs:158`.
- **Failure scenario:** A local client submits a large permitted PtyInput frame to a harness not reading stdin. The blocking `write_all` fills the PTY input queue and never returns. The handler holds the global registry mutex throughout, so other clients cannot list, attach, merge or switch, output cannot update scrollback, and shutdown waits forever for that same mutex (`aihubd/src/lib.rs:345`).
- **Fix:** Release the registry lock before PTY I/O and use bounded per-session input queues with cancellation/timeouts that do not strand a blocking writer.

### F8 — P2: Typing during a fragmented daemon frame corrupts the TUI's IPC reader

- **Location:** `aihub/src/lib.rs:176` and `:233`; `aihub/src/connection.rs:105`.
- **Failure scenario:** `recv_msg` consumes the length and part of a PTY-output payload, then waits for remaining bytes. A keyboard/resize event wins `tokio::select!`, dropping that future and its buffer. The next loop reads remaining payload bytes as a new length prefix, causing a bogus oversized frame/error or a hang and unnecessary reconnection during normal interactive use.
- **Fix:** Keep a persistent framed decoder or run a dedicated reader task feeding a channel so selection cancels only a channel receive, never partial framing state.

### F9 — P2: Normal TUI sessions never enter the routing workflow

- **Location:** `aihub/src/lib.rs:285`; daemon gate `aihubd/src/lib.rs:376`; fallback bypass `aihubd/src/lib.rs:619`.
- **Failure scenario:** Start bare `aihub`, type a task into Claude, and switch to Autonomous mode. NewSession always supplies `initial_prompt: None`, typed task text only goes to PtyInput, and the TUI sends no RouteRequest. Telemetry only recommends for sessions with a saved prompt, so this ordinary workflow never recommends or autonomously switches. Even an IPC RouteRequest uses only `classify`, never the implemented LLM fallback.
- **Fix:** Add a task-submission boundary that supplies routing context and invoke the ambiguous/long-prompt fallback from the daemon recommendation path.

### F10 — P2: The daemon dispatches the router's explicit no-launch placeholder

- **Location:** `aihub-router/src/lib.rs:266`; consumer `aihubd/src/lib.rs:631`.
- **Failure scenario:** With every slot exhausted, route returns an Ok recommendation with a placeholder harness, no hold and a reason saying not to launch. An Autonomous session on another harness interprets the missing hold as zero and switches to that unavailable placeholder. The assisted acceptance path also launches the recommendation without checking supply (`aihub/src/keys.rs:127`).
- **Fix:** Represent no capacity as a non-dispatchable typed result/error and guard both autonomous dispatch and assisted acceptance.

### F11 — P2: Codex tool-call records abort extraction of the entire transcript

- **Location:** `aihub-memory/src/transcript/codex.rs:70`.
- **Failure scenario:** A Codex transcript contains a response_item whose payload is a function_call with no role/content, followed by its final assistant message. The `?` on `role` or `content` returns None for the whole file instead of skipping the non-message item. Switching away from this session produces a no-last-turn brief and loses decisions despite a valid final answer in the log.
- **Fix:** Filter response_item payloads for message records and skip unsupported/tool items instead of propagating None out of file extraction.

### F12 — P2: Terminal initialization errors leave raw mode enabled

- **Location:** `aihub/src/terminal.rs:14`.
- **Failure scenario:** Raw mode succeeds but writing/flushing the alternate-screen sequence fails (for example stdout is redirected to a failing destination while stdin still points at the terminal). `new()` returns Err before constructing the guard, so Drop never restores terminal settings. This is an error return, so the panic hook does not help.
- **Fix:** Construct the cleanup guard immediately after enabling raw mode, or explicitly restore on every subsequent initialization error.

### F13 — P2: Session-scoped broadcasts alter unrelated clients' state and recommendations

- **Location:** `aihub/src/lib.rs:366` and `:388`; broadcaster `aihubd/src/lib.rs:175` and `:621`.
- **Failure scenario:** Two clients attach to different sessions. Switching or exiting session B updates client A's harness badge or active flag because the TUI ignores session_id on these events. A RouteRecommendation for B is broadcast without any session identifier and overwrites A's recommendation; accepting it switches A according to B's task. Reattach also restores only bytes/id, leaving the default Claude/main/Assisted metadata (`aihub/src/lib.rs:336`).
- **Fix:** Filter scoped events by session, fetch SessionSummary on attach, and target or identify route recommendations so other sessions cannot consume them.

### F14 — P2: Merge cannot return work to an originating linked checkout

- **Location:** `aihub-git/src/lib.rs:81` and `:306`.
- **Failure scenario:** Launch a session from a linked checkout on `feature`, while the repository's main checkout is on `main`. Creation correctly records feature as base, but finish always selects the first worktree entry as the merge destination, then refuses because main is not feature. The originating checkout is never selected, so the documented merge into the user's original branch is unavailable for this supported repository shape.
- **Fix:** Preserve/resolve the original checkout identity and validate that checkout's branch and cleanliness before merging there.
