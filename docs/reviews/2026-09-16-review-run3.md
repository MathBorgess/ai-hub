## New/residual findings, ordered by severity

### R1 — P1: inactive is mistaken for confirmed group quiescence

**Location:** `aihubd/src/lib.rs:632–640,798–802,1197,1372`.

**Scenario:** (a) leader forks a same-group TERM/HUP-ignoring writer with redirected stdio and exits normally; watch marks the session inactive; confirm merge or switch. (b) signal/reap/deadline failure returns `stop_unconfirmed`, which also sets inactive; retry switch, or repeat merge preview/confirmation. In both cases `quiesce` returns early without proving group extinction, so Git can finalize or a new harness can start while the descendant still writes. The mutex serializes requests but does not prevent a second client exploiting this state after the first request returns.

**Fix:** represent leader exit, stop failure and confirmed group-stop separately. Retain the group handle and run/retry the barrier before every destructive finalization/replacement unless confirmed quiescence for that generation is stored. Shutdown must also retry uncertain groups.

**Coverage gap:** first-error refusal tests stop after one request; redirected daemon fixture's leader waits until stop. Add natural-leader-exit plus merge/switch, and repeated/two-client operations after StopUnconfirmed; assert no git_finish/spawn until confirmed.

### R2 — P1: blocking child.wait under reap_lock defeats the stop deadline

**Location:** `aihub-pty/src/spawn.rs:220,377–386`; daemon awaits stop with registry held at `aihubd/src/lib.rs:638`.

**Scenario:** child installs TERM/HUP ignore, redirects all PTY descriptors, then remains alive (`exec >/dev/null 2>&1 </dev/null; ...`). Reader sees EOF, takes reap_lock and blocks in `child.wait()`. Stop sends TERM/HUP once and then blocks acquiring reap_lock; it never reaches SIGKILL escalation or deadline checks. All state-locked daemon requests/shutdown can hang. This is a live direct child, distinct from the test where the direct child exits and only its descendant remains.

**Fix:** never hold a mutex needed by escalation across blocking wait. Use a single reaper with nonblocking wait/notification or short nonblocking critical sections and a separate deadline-driven signal path. Return an explicit uncertain-stop error on failure.

**Coverage gap:** no EOF-with-live-signal-ignoring-leader test. Use a child readiness marker, close stdio, assert stop completes/errors within its deadline and B stays responsive. A timeout outside spawn_blocking alone cannot stop the blocked thread.

### R3 — P2: assisted holds use epoch units while the router supplies duration

**Location:** `aihub-router/src/lib.rs:516–520,222`; `aihub/src/keys.rs:184–196`; `aihubd/src/lib.rs:1124–1135`.

**Scenario:** real quota resets in 30 seconds and router returns `holds_until_s:Some(30)`. TUI compares 30 with current Unix seconds, decides the hold expired, and sends SwitchHarness. The daemon treats the same message as a manual override, so acceptance immediately bypasses the hold. The footer has the same epoch interpretation.

**Fix:** define one wire semantic (prefer explicit deadline or named duration converted on receipt), enforce acceptance against the daemon's current recommendation, and distinguish acceptance from a deliberate manual override.

**Coverage gap:** daemon fixture uses duration 30; TUI fixture uses epoch 50400. Both pass separately. Add real router→DaemonMessage→TUI key→daemon spawn test with a controlled clock.

### R4 — P2: synchronous spool lock held across await can starve/deadlock the runtime

**Location:** `aihub-memory/src/ai_memory.rs:262,287,365,458`; daemon independent drain `aihubd/src/lib.rs:933`.

**Scenario:** a drain owns the flock and awaits a slow peer. Another record/drain synchronously calls File::lock on the executor thread. On a current-thread runtime this prevents the owner/timer from progressing; on the production multithread runtime enough concurrent clients exhaust workers with the same result. A different process indefinitely holding the lock also produces an unbounded wait. Moving the operation outside the registry does not fix this executor-level blockage.

**Fix:** isolate blocking filesystem/lock acquisition off executor threads, serialize in-process work asynchronously, bound acquisition/cancellation, and design queue transactions so lock ownership is compatible with network awaits (or avoid holding it across network entirely).

**Coverage gap:** current lock test checks try_lock on two handles synchronously; no concurrent async record/drain with a silent server. Add owned slow-peer plus simultaneous appends/drain and responsive timer/shutdown assertions.

### R5 — P2: MCP result/framing validation still permits false success and rejects valid responses

**Location:** `aihub-memory/src/ai_memory.rs:539–570,590–594,624–631,644–671`.

**Scenario:** HTTP 200 body `{"jsonrpc":"2.0","id":1,"result":null}` is accepted, allowing a spooled record to be removed without a valid CallToolResult. A legal chunked JSON response retains chunk markers and is rejected; an SSE notification followed by matching result returns the first object then fails ID matching. Multiline/multiple SSE events are not parsed by event boundaries. A peer sending headers without the terminating blank line can grow resp_bytes without the 1 MiB cap until the time deadline; valid SSE kept open is read until timeout despite receiving a complete result.

**Fix:** use a bounded HTTP decoder (including headers/chunking/content length), incremental SSE event parsing keyed to request ID, and validate a real tool-result object and error semantics before acknowledgment.

**Coverage gap:** fixtures close the socket and supply simple content-length JSON/single-event SSE. Add null/scalar result, notification-before-result, multiline multiple events, chunked response, open SSE stream and oversized headers.

### R6 — P2: interrupted append or legacy record permanently blocks later audit delivery

**Location:** `aihub-memory/src/ai_memory.rs:285–307,412–413`.

**Scenario:** disk fills or daemon dies partway through writeln, leaving a JSON prefix with no newline. A later successful append concatenates a valid record onto it. Drain preserves the malformed first line and stops, returning Ok(0) forever; valid later records never drain and no actionable corruption error appears. Existing old path-only spool records also fail the new required schema and produce the same permanent queue obstruction after upgrade.

**Fix:** make appends transactional or recover partial tails under lock; quarantine/report invalid records while preserving bytes and continue recoverable records; migrate/version old schema explicitly. Sync directory creation when promising crash durability of a newly created spool.

**Coverage gap:** pre-rename injection exercises atomic rewrite only, not partial append, full disk, malformed head, or upgrade. Add partial-write/restart/recovery fixtures and assert later valid records deliver with visible corruption/migration diagnostics.

### R7 — P2: first record bypasses spool byte limit; privacy enforcement is best effort

**Location:** `aihub-memory/src/ai_memory.rs:370–397,410,418–426,452–458`.

**Scenario:** with no handoffs.jsonl, a record larger than 10 MiB skips every size check and is written successfully (goal/decisions are not bounded here). Separately, point AIHUB_DATA_DIR to a writable shared directory owned by another UID whose chmod is denied: ensure_spool_dir ignores the failure and reports success. Existing writable spool/lock paths likewise ignore chmod failure; symlinks are followed. Thus 0700/0600 cannot be guaranteed wherever the data directory points.

**Fix:** check single-record and resulting-size limits even when absent; propagate chmod failures and validate ownership/file type/mode through opened descriptors, rejecting unsafe/symlink targets as appropriate.

**Coverage gap:** limit fixture pre-creates a full file; permission test creates new user-owned files only. Add first-oversized-record, existing permissive file and denied-permission tests with a filesystem seam where needed.

### R8 — P2: a routed lane can still launch an uncontrolled/default model

**Location:** `aihub-router/src/lib.rs:218–222,391–412`; `aihubd/src/lib.rs:1259,1323,1361`; `aihub-pty/src/harness.rs:75`.

Also a recommendation selecting another model/lane within the current harness is ignored: autonomous compares only harness, and assisted switch returns early for the same active harness.

### R9 — P2: installed PATH resolves a harness file but can omit its interpreter

**Location:** `scripts/install.sh:321–350`; `scripts/test-install.sh:109–131`.

**Scenario:** `~/.local/bin/claude` has `#!/usr/bin/env node`, and node exists only in `/opt/homebrew/bin` or an nvm directory, with no other harness in that directory. Installing shell can execute it, but installer copies only harness directories plus system directories. command -v succeeds under the rendered PATH; actual launch fails to find node.

### R10 — P2: pending autonomous dispatch lacks recommendation identity and cancels itself during quiesce

**Location:** `aihubd/src/lib.rs:662–690,643–644,1376`.

**Scenario:** hold timer is saved in session.tasks. When it fires it calls switch, whose successful quiesce aborts every task in that vector, including the current timer task. If memory_extractor then yields, the switch can be canceled after stopping the outgoing child and before replacement. The current test's ready extractor/dummy stop lets execution finish without a cancellation point. Separately, a new task or NoCapacity result does not invalidate an older hold timer; eligibility checks only mode/active/different harness, so an old recommendation can act on new context.

**Fix:** separate lifecycle watcher handles from scheduled recommendation tasks; remove/replace the current hold task safely and validate a generation/recommendation ID plus current capacity atomically at dispatch.

**Coverage gap:** one timer, immediate seams and unchanged task only. Add a yielding extractor and replace-task/NoCapacity/mode-change race fixtures; assert the full stop→handoff→spawn outcome and latest recommendation ownership.

## Process-lifecycle mutex poisoning (direction, not a separate blocker)

The cited expect calls should not be the long-term supervisor contract. A panic while reap_lock/exit_code is held causes subsequent stop to panic instead of establishing quiescence; spawn_blocking's JoinError is translated to a PtyError, so that path does not itself legitimately report success. Drop invokes the same barrier synchronously and may panic again (including during unwinding). A panic before successful reaping can leave the child unreaped; a reader panic while holding scrollback can leave later snapshots unusable.

Prefer one reaping owner, explicit lifecycle/error states, and poison-to-error propagation on operations that cannot prove invariants. Recover poisoned data only where the invariant can actually be reconstructed (e.g. discard/rebuild scrollback); never translate uncertainty into stopped. Cleanup should attempt best-effort signals/reap without panicking, with bounded diagnostics. Add injected panic/poison tests. This recommendation alone is not a release blocker; R1/R2 are concrete independent blockers.

## Security and real-system conclusions

- No direct sink for the **credential-source values** was found in inspected probe/adapter flow: vendor tokens are HTTP headers/cookies, CSRF is a header, AI_MEMORY_AUTH_TOKEN is an Authorization header (`ai_memory.rs:514`), HTTP adapter errors collapse to (), and catalog stderr is discarded. No real secret was read. Generated briefs pass the redactor at `aihub-memory/src/brief.rs:75–76`.
- I cannot confirm the universal statement “no token can reach any log, IPC, error or file.” PTY forwarding intentionally carries arbitrary child output (`aihubd/src/lib.rs:784–790`), including a secret a harness prints. Public SpooledRecord/from_brief/record APIs trust caller text and do not apply a sanitizer at the persistence boundary (`ai_memory.rs:70–101,367`); a raw externally supplied brief with a credential assignment will persist it. Keep typed credentials out of printable structs/errors and sanitize/validate at the audit boundary as defense in depth. This review finds no evidence that the private credential readers directly print their token, which is narrower than universal taint proof.
- Spool modes are requested for custom data directories, an improvement over relying on socket-parent privacy, but ignored permission errors make the blanket guarantee false (R7). Auth token itself is not a SpooledRecord field. Configurable raw HTTP server URL still permits sending Authorization over non-loopback plaintext; no remote/TLS guarantee is implied.
- **Installer-test isolation:** `test-install.sh:59–86` creates a fresh temporary HOME, prepends its fake launchctl, uses `--bin-dir` and `--no-start`; uninstall also receives fake HOME/PATH. Thus the inspected test path does not bootstrap real agents or curl default port 49374. It writes that port into an unstarted temp plist. Harness lookup can inspect inherited PATH but does not execute real harnesses. The test downloads/initializes the pinned real sidecar inside temporary paths; it is not an offline test.
- **Production installer is intentionally different:** normal install writes the user's HOME, calls real launchctl and queries 49374 (`install.sh:460–470`). It cannot truthfully be described as never touching those surfaces; the isolated invocation is the safe test contract. Uninstall still bootouts/removes both plists unconditionally (`uninstall.sh:80–82`) even when the binary marker protects a pre-existing ai-memory binary (:93–100); pre-existing service ownership is not covered by that test.
- **Live sidecar script has weaker isolation:** `scripts/e2e-ai-memory.sh` passes explicit temp data/config, but retains actual HOME, inherited auth/environment, and invokes CLI without explicit --config in the Rust test. Free-port discovery releases its socket before bind; no explicit exclusion of 49374; offline leg assumes 59999 free. It does not call launchctl. Strengthen environment/port ownership before describing it as categorically unable to touch the real system. Its readiness curl and Rust helper read_to_end also lack deadlines.
